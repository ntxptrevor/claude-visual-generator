## Google access and DWD

### RB-001 Any Google call fails with "403 unauthorized_client" or "Client is unauthorized to retrieve access tokens using this method".

- **Likely cause:** The service account's Client ID is not listed under domain-wide delegation, or it was listed with a different scope set than the code now asks for.
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. Ask Trevor for the service-account Client ID (a long number). He can print it with: gcloud iam service-accounts describe ntxp-workspace-agent@ntxp-workspace-agent.iam.gserviceaccount.com --format='value(oauth2ClientId)'.
2. Sign in to https://admin.google.com/ac/owl/domainwidedelegation as a Workspace super admin.
3. Find the row with that Client ID. If there is none, click Add new.
4. Get the full scope list by running: python3 scripts/google_workspace/ntxp_google_access.py scopes --csv. Paste it into the OAuth scopes box exactly, replacing what is there, and click Authorize.
5. Wait 5 minutes (Google can take up to 24 hours, usually minutes), then test with: python3 scripts/google_workspace/ntxp_google_access.py whoami.
6. If it still fails after one hour, escalate.

### RB-002 One Google area works (for example Gmail) but another fails with "access_denied" or "Requested scope not authorized" (often Admin Reports, Contacts or Calendar).

- **Likely cause:** A scope was added to the access layer after delegation was set up, so the delegation entry is missing it.
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. Run: python3 scripts/google_workspace/ntxp_google_access.py scopes --csv and copy the output.
2. Open https://admin.google.com/ac/owl/domainwidedelegation, click the NTXP Workspace Agent row, then Edit.
3. Compare the scope list. Replace it with the full copied list (do not remove scopes that are still in the copied list).
4. Save, wait 5 minutes, retry the failing screen in the admin console.
5. Write the date and the scope you added into this entry's notes in the Admin Runbook sheet.

### RB-003 setup_dwd.sh prints "Key creation blocked by org policy; using keyless mode instead", or Cloud Console says service account key creation is disabled.

- **Likely cause:** The Google Cloud org policy iam.disableServiceAccountKeyCreation is on. Keyless mode works on a laptop but the VPS container has no Google login, so the admin console needs a key.
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. Do not try to switch the policy off for the whole organization.
2. Escalate to Trevor with the exact message. He decides between (a) a policy exception for the single project ntxp-workspace-agent only, or (b) keyless mode with a workload identity on the VPS.
3. If an exception is approved: in Cloud Console go to IAM & Admin > Organization Policies, select project ntxp-workspace-agent, open 'Disable service account key creation', choose Override parent's policy, set Enforcement Off, save.
4. Re-run: bash scripts/google_workspace/setup_dwd.sh. Move the key contents into the NTXP vault as NTXP_GOOGLE_SA_KEY and delete the local file in ~/.config/ntxp/.
5. Re-enable the policy override (Enforcement On) once the key is created.

### RB-004 Error says the user to impersonate is outside the domain, or "subject must be an @ntxpllc.com user".

- **Likely cause:** Someone asked the tool to act as a personal Gmail, a contractor address, or a misspelled address. The access layer refuses anything outside ntxpllc.com by design.
- **Escalate to:** Trevor (operations)
- **Tier:** 0 - look only, no change
- **Updated:** 2026-10-09

**Steps**

1. Check the address for typos (for example ntxpllc.co or ntxp.com).
2. Use the person's @ntxpllc.com address. External people cannot be impersonated; ask them to share the file or message instead.
3. Do not change NTXP_GOOGLE_DOMAIN to get around this.

### RB-005 "invalid_grant" or "Invalid email or User ID" when reading one person's mailbox or Drive.

- **Likely cause:** That account is suspended, deleted, renamed, or has no Gmail/Drive licence.
- **Escalate to:** Trevor (operations)
- **Tier:** 0 - look only, no change
- **Updated:** 2026-10-09

**Steps**

1. Open https://admin.google.com > Directory > Users and search the name.
2. If suspended or deleted, this is expected; the analytics skip that person. Note it on the flag and dismiss.
3. If renamed, use the new primary address (aliases cannot be impersonated).
4. If the account has no licence, Trevor decides whether to assign one.

### RB-006 Server log shows a JSON decode error or "Could not deserialize key data" on start-up; every Google source shows error.

- **Likely cause:** NTXP_GOOGLE_SA_KEY was pasted with broken line breaks, extra quotes, or only part of the JSON.
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. Open the NTXP vault entry for NTXP_GOOGLE_SA_KEY and confirm it starts with { and ends with } and contains "private_key".
2. In Hostinger hPanel > VPS > Docker Manager > ntxp-admin project > Environment, paste the value again as one line (the \n sequences inside private_key must stay as the two characters backslash and n).
3. Restart the project (Docker Manager > Restart) and check /api/health from the console's Status card.
4. Never paste the key into chat, email, a ticket or this runbook.

### RB-007 The console Status card shows gmail, drive, calendar, contacts, directory and reports as "unconfigured".

- **Likely cause:** The VPS project environment is missing NTXP_GOOGLE_SA_KEY (or NTXP_GOOGLE_SA_EMAIL) or NTXP_GOOGLE_ADMIN_SUBJECT, or NTXP_ADMIN_DEMO is still on.
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. In hPanel open the VPS > Docker Manager > ntxp-admin > Environment.
2. Confirm NTXP_GOOGLE_SA_KEY and NTXP_GOOGLE_ADMIN_SUBJECT are present and not empty. Copy missing values from the NTXP vault.
3. Confirm NTXP_ADMIN_DEMO is empty or false in production.
4. Restart the project and reload the Status card.

### RB-008 User list or login reports fail with "Not Authorized to access this resource/api" while Gmail and Drive work.

- **Likely cause:** NTXP_GOOGLE_ADMIN_SUBJECT is a normal user, not a Workspace super admin; the Admin Directory and Reports APIs need an admin to impersonate.
- **Escalate to:** Alison (owner)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. In https://admin.google.com > Account > Admin roles, check that the account in NTXP_GOOGLE_ADMIN_SUBJECT holds Super Admin.
2. If not, set NTXP_GOOGLE_ADMIN_SUBJECT to an account that does (ask Trevor which).
3. Granting a new super admin is an owner decision; do not grant it yourself.

### RB-009 A Google service-account key, OAuth client secret or API key was pasted somewhere public (GitHub, email, chat, a shared doc).

- **Likely cause:** Human or agent error. The repo is public; anything committed is exposed immediately.
- **Escalate to:** Alison (owner)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. Treat it as an incident now, not later. Tell Trevor and Alison by phone.
2. Trevor: delete the exposed key in Cloud Console > IAM & Admin > Service Accounts > ntxp-workspace-agent > Keys.
3. Trevor: if a service-account key leaked, remove the Client ID at https://admin.google.com/ac/owl/domainwidedelegation until a new key is issued.
4. Create a new key, store it only in the NTXP vault and the VPS project environment, restart the project.
5. Remove the secret from the place it leaked (a git history rewrite needs Trevor). Log what happened in the Learning tab.

## Admin console login

### RB-010 After choosing a Google account, admin.ntxpllc.com shows the oauth2-proxy "403 Forbidden / Permission Denied" page for Trevor or Alison.

- **Likely cause:** The browser signed in with a different Google account (personal Gmail or an alias), or the address is missing or misspelled in admin_console/deploy/emails.txt (and the inline copy in docker-compose.yaml).
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. Open https://admin.ntxpllc.com/oauth2/sign_out, then sign in again and pick exactly trevor@ntxpllc.com or alison@ntxpllc.com.
2. Try a private/incognito window to rule out a second signed-in Google account.
3. If it still fails, Trevor checks emails.txt and the emails config block in docker-compose.yaml: each address on its own line, lower case, no spaces.
4. Editing the allowed list is a permission change (Tier 3) and needs owner approval before redeploy.

### RB-011 Google shows "Error 400: redirect_uri_mismatch" when signing in.

- **Likely cause:** The OAuth web client in Google Cloud does not list https://admin.ntxpllc.com/oauth2/callback exactly, or OAUTH2_PROXY_CLIENT_ID points at a different client.
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. In Google Cloud Console > APIs & Services > Credentials, open the 'NTXP Admin Console' OAuth client.
2. Under Authorized redirect URIs make sure this exact line exists: https://admin.ntxpllc.com/oauth2/callback (https, no trailing slash).
3. Confirm the Client ID shown there matches OAUTH2_PROXY_CLIENT_ID in the VPS project environment.
4. Save, wait 5 minutes, try again.

### RB-012 The page keeps bouncing between Google and admin.ntxpllc.com (sign-in loop), or says "cookie not found" / CSRF error.

- **Likely cause:** The cookie secret changed or is the wrong length, the site was opened over http, or the browser blocks cookies for the site.
- **Escalate to:** Trevor (operations)
- **Tier:** 2 - tell the owners, then act
- **Updated:** 2026-10-09

**Steps**

1. Clear cookies for admin.ntxpllc.com (browser settings > Privacy > Site data), close the tab, open https://admin.ntxpllc.com again.
2. Make sure the address starts with https://. The proxy only sets secure cookies.
3. Trevor: confirm OAUTH2_PROXY_COOKIE_SECRET is exactly 32 characters (generated as in DEPLOY.md step b). If it was regenerated, everyone must sign in again; that is expected.
4. Trevor: confirm the VPS clock is correct (timedatectl). A clock off by minutes breaks Google tokens.

### RB-013 Google sign-in succeeds but the console shows {"code": "not_owner"} or a blank panel with 403 on every /api call.

- **Likely cause:** The app is not receiving the X-Forwarded-Email header: oauth2-proxy is missing --pass-user-headers, or someone reached the app container directly.
- **Escalate to:** Trevor (operations)
- **Tier:** 3 - explain and wait for owner approval
- **Updated:** 2026-10-09

**Steps**

1. Trevor: check the oauth2-proxy command in docker-compose.yaml includes --pass-user-headers=true and --upstream=http://app:8080.
2. Confirm the app service has no ports: section (it must only be reachable through oauth2-proxy).
3. Redeploy and retry. Do not weaken the server's owner check to make it work.

### RB-014 An NTXP employee (not Trevor or Alison) reports they get 403 at admin.ntxpllc.com.

- **Likely cause:** Working as designed. Only the two owners may use the console.
- **Escalate to:** Alison (owner)
- **Tier:** 0 - look only, no change
- **Updated:** 2026-10-09

**Steps**

1. Tell the employee the console is owner-only and no action is needed.
2. Do not add them to emails.txt. Access for anyone else is an owner decision.
3. If the employee needs data from the console, ask Trevor to share the specific report.

### RB-015 After signing in, the page shows "502 Bad Gateway" or "upstream connect error".

- **Likely cause:** oauth2-proxy is up but the app container is stopped, crashing or still starting.
- **Escalate to:** Trevor (operations)
- **Tier:** 0 - look only, no change
- **Updated:** 2026-10-09

**Steps**

1. Wait 60 seconds and reload; the app may be restarting.
2. If it persists, follow RB-016 (container down).

## Deploy, VPS and DNS

### RB-016 admin.ntxpllc.com does not load, shows 502, or Docker Manager shows a container as Exited/Restarting.

- **Likely cause:** The app or proxy container crashed (bad env value, code error after a deploy) or the VPS rebooted.
- **Escalate to:** Trevor (operations)
- **Tier:** 2 - tell the owners, then act
- **Updated:** 2026-10-09

**Steps**

1. In hPanel > VPS > Docker Manager, open the ntxp-admin project and note which container is not Running.
2. Open its Logs and copy the last 30 lines into the ticket (remove anything that looks like a key).
3. Click Restart on the project (API: VPS_restartProjectV1). Restart keeps data.
